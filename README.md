# 案件管理システム（社内・完全ローカル運用）

案件情報を管理するデータベースとWeb画面です。**インターネットには一切公開せず、社内のPC/サーバ上だけ**で動かすことを前提にしています。

- **通信はHTTPS（暗号化）**。パスワード等が平文で流れないようにしています。
- ログイン制（ID／パスワード）。ユーザーはシステム管理者が事前登録します。
- **9月始まり・8月締め**の会計期（59期＝2026/9〜2027/8）に対応。案件は部門ごとに**完成月**で管理します。
- 3段階の権限（システム管理者／管理者＝部門長／一般）と、ユーザーと部門の紐づけ（複数部門可）。
- 案件の閲覧・登録・編集・エクスポート（CSV・Excel・PDF）と、**数字まとめ**（予実・損益・カテゴリー別・商品カテゴリ別・確度別を月／四半期／半期／通期で集計）。
- 案件は 完成月／担当者／区分／カテゴリー／案件名／**取引先**／**エンドユーザ**／**商品カテゴリ**／確度／売上／仕入 …で管理します（取引先・エンドユーザは過去入力が候補表示、商品カテゴリはマスタから選択）。
- ログイン後に**アクセスする部門を選択**する方式（上部の「部門切替」でいつでも変更可能）。
- データは1つのファイル（SQLite）に保存され、そのファイルをコピーするだけでバックアップできます。

> **権限の考え方**
> - **システム管理者**: 全権。ユーザー管理・マスタ管理を含むすべての操作が可能。ユーザーの**削除**もできます（担当していた過去案件には担当者名だけが残ります）。
> - **管理者（部門長）**: **所属部門**と、別枠で選んだ**閲覧・編集可能な部門**のみ閲覧・編集できます。案件管理の担当者候補には、所属部門にのみ氏名が表示されます（無関係な部門には出ません）。商品カテゴリのマスタ管理も可能です。
> - **一般ユーザー**: 自部門の案件を閲覧でき、編集できるのは自分が担当の案件のみ。インポートはできません。
>
> ※ PDF出力の日本語表示には IPAexゴシックフォントを同梱・埋め込みしています
> （ライセンス: `app/static/fonts/IPA_Font_License_Agreement_v1.0.txt`）。

## 1. 動かすのに必要なもの

- **Docker Desktop**（Windows / Mac）または **Docker Engine**（Linux）
  - これ1つ入れれば、Python等を個別にインストールする必要はありません。

## 2. セットアップ手順（初回のみ）

### ① 設定ファイルを作る
プロジェクトのフォルダで、サンプルをコピーして `.env` を作ります。

```bash
cp .env.example .env
```

`.env` を開き、次の2点を設定してください。

- `SECRET_KEY` … **推測されない長い文字列**に変更（生成例: `python -c "import secrets; print(secrets.token_hex(32))"`）
- `CERT_HOSTS` … このサーバに**アクセスするときのアドレス**を入れる（HTTPS証明書に登録されます）
  - 例: 社内の他PCからサーバ(IP 192.168.1.10)にアクセスするなら `CERT_HOSTS=localhost,192.168.1.10`

### ② 起動する

```bash
docker compose up -d --build
```

初回起動時に、自動で以下が行われます。
- **HTTPS用の証明書を自動生成**（自己署名。`CERT_HOSTS` の値を登録）
- データベースのテーブル作成
- 確度ランク（○／A／B／C／D／E／×）・区分（期初計画／新規）・部門（第2営業部 ほか）・
  第2営業部のカテゴリー（Ri／Or／Au／Kd／NM／Ot）の初期値投入

### ③ 最初のシステム管理者アカウントを作る
起動中のコンテナ内で、対話形式でシステム管理者を作成します。

```bash
docker compose exec web flask create-admin
```

ログインID・氏名・パスワードを聞かれるので入力してください。

### ④ ブラウザでアクセス

```
https://localhost
```

作成した管理者でログインできます。
社内の**別のPC**からアクセスさせる場合は、サーバPCのIPアドレスを使います（例: `https://192.168.1.10`）。
（`HTTPS_PORT` を443以外にした場合は `https://<サーバ>:<ポート>` の形になります）

> **初回に「この接続ではプライバシーが保護されません」等の警告が出ます。**
> 自己署名証明書のためで、社内LAN内の利用であれば「詳細設定 →〈このサイトにアクセスする〉」で進めて問題ありません。
> 警告を消したい場合は下記「HTTPS（証明書）について」を参照してください。

## 3. 使い方

### ユーザー登録（システム管理者）
1. システム管理者でログイン → 上部メニュー「ユーザー管理」
2. 「＋ ユーザーを登録」でログインID・氏名・**権限**・**所属部門（複数可）**を入力。
   権限が「管理者」の場合は、所属とは別枠で**閲覧・編集可能な部門**も選べます
   （この部門の担当者候補には氏名は表示されません）。
3. 登録すると**初期パスワードが1度だけ画面に表示**されます。本人に伝えてください。
4. 各利用者は初回ログイン時にパスワード変更を求められます。
5. パスワードを忘れた場合は、システム管理者が「PWリセット」で再発行できます。
6. 退職者などは「無効化」でログイン不可にできます。「削除」すると一覧から消えますが、
   過去に担当していた案件には**担当者名だけが残ります**。
7. 「カテゴリー管理」から部門ごとのカテゴリーを、「商品カテゴリ管理」（管理者も可）から
   部門ごとの商品カテゴリを追加・編集できます。

### 部門の選択・切り替え
ログイン後、複数部門にアクセスできる場合は**部門選択画面**が表示されます。
選択した部門はセッション中保持され、上部メニューの「**部門切替**」からいつでも変更できます。
（1部門のみの利用者は自動的にその部門になります。）

### 案件管理表
上部メニュー「案件管理」で、選択中の部門の案件が**完成月ごと**にまとまって表示されます
（各月に売上・仕入・売上総利益の小計）。「＋ 案件を登録」で
担当者／区分／カテゴリー／案件名／**取引先**／**エンドユーザ**／**商品カテゴリ**／確度／
売上／仕入／見込み・対応工数／備考を入力します（売上総利益は「売上−仕入」で自動計算）。
取引先・エンドユーザは過去に入力した値が候補として表示されます。
右上の **CSV / Excel / PDF** で出力できます（インポートは管理者以上のみ）。

### 数字まとめ
上部メニュー「数字まとめ」で、部門ごとに以下を確認できます（集計単位は月／四半期／半期／通期）。
- **予実まとめ**: 実績（確度○）／期初計画／計画差異／達成率
- **損益まとめ**: 売上・仕入・売上総利益・粗利率と、月次入力の販管費との対比
- **カテゴリー別**（通期）: 売上・売上総利益の計画／実績
- **商品カテゴリ別**（通期）: 商品カテゴリごとの売上・売上総利益の計画／実績
- **確度別**（通期）: 確度ごとの売上・仕入・売上総利益・粗利率
- **販管費入力**: 月ごとに手入力（四半期・半期・通期は自動合計）

## 4. バックアップ

データは `data/app.db`（SQLiteファイル）に入っています。
**このファイルをコピーするだけ**でバックアップになります。定期的に別の場所へコピーしてください。

```bash
# 例: 日付つきでコピー
cp data/app.db backups/app_$(date +%Y%m%d).db
```

## 5. 停止・再起動

```bash
docker compose down      # 停止
docker compose up -d     # 起動
```

## 6. HTTPS（証明書）について

本システムはHTTPSで通信します。証明書の運用は2通りあります。

### A. 自己署名証明書（既定・すぐ使える）
初回起動時に自動生成されます。設定不要ですぐHTTPSになりますが、ブラウザに警告が出ます。
社内LAN内であれば、警告画面で「このサイトにアクセスする」を選べば利用できます。

- アクセスに使うIP/ホスト名を変えたときは、証明書を作り直してください（`certs/` の中身を消して再起動すれば自動再生成、または下記スクリプト）。

```bash
# 例: サーバIPを登録して作り直す
docker compose exec web sh /app/scripts/gen-cert.sh /app/certs "localhost,192.168.1.10"
docker compose restart web
```

### B. 警告を出さない（社内で信頼される証明書を使う）
各PCに「信頼するCA証明書」を1回インストールする方法です。おすすめは **mkcert**（無料）です。

1. サーバ管理者のPCで mkcert を使い、ローカルCAと、サーバのIP/ホスト名向けの証明書を発行
2. 発行された証明書・鍵を `certs/server.crt` `certs/server.key` として配置し `docker compose restart web`
3. mkcert のローカルCA（`mkcert -CAROOT` にある rootCA.pem）を、アクセスする各PCに「信頼されたルート証明機関」としてインストール

これで警告なしのHTTPSになります。社内に独自の認証局(CA)がある場合は、そのCA発行の証明書を `certs/` に置いても構いません。

## 7. セキュリティ上の注意

- **インターネットに公開しないでください。** 社内LAN内でのみ利用します。
- ルーターのポート開放（ポートフォワーディング）はしないでください。
- 通信はHTTPSで暗号化されます（証明書は上記のとおり運用してください）。
- 初期パスワードは必ず本人に変更させてください。
- 管理者アカウントの管理に注意してください。
- `certs/` 内の秘密鍵（server.key）や `.env` は共有・コミットしないでください。

## 開発者向け情報

### ローカル（Docker無し）で動かす

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export FLASK_APP=wsgi.py          # Windows(PowerShell): $env:FLASK_APP="wsgi.py"
flask db upgrade                  # テーブル作成
flask seed-masters                # マスタ初期値（確度・区分・部門・カテゴリー）
flask create-admin                # システム管理者作成
flask run --host 0.0.0.0 --port 8000    # 開発用。この起動はHTTP（本番はDockerでHTTPS）
```

> 開発用の `flask run` はHTTPです（手元での動作確認用）。本番運用はDocker（HTTPS）を使ってください。

### テスト

```bash
pytest
```

### 項目（カラム）を追加したいとき（拡張）

1. `app/models.py` にカラムを追加
2. マイグレーションを生成して適用

```bash
flask db migrate -m "add xxx column"
flask db upgrade
```

（Docker運用中は次回起動時に `flask db upgrade` が自動実行されます）

### 選択肢（確度・区分・カテゴリー・部門）を増やしたいとき

カテゴリーはシステム管理者でログインし「ユーザー管理 → カテゴリー管理」から部門ごとに追加・
表示切替ができます。商品カテゴリは「商品カテゴリ管理」から（システム管理者・部門管理者が）
部門ごとに追加・表示切替ができます。確度・区分・部門・商品カテゴリの初期値は
`app/cli.py` の `seed-masters` に定義しています。

### 会計期の設定

会計期の定義は `app/fiscal.py` に集約しています。対象期は `CURRENT_FISCAL_PERIOD`（既定59）で、
59期＝2026/9開始をアンカーに月／四半期／半期／通期のまとめ方を決めています。

### 構成

```
app/
├─ __init__.py     アプリ生成（app factory）
├─ config.py       設定
├─ extensions.py   DB/ログイン等の拡張
├─ fiscal.py       会計期（月→四半期/半期/通期）ヘルパー
├─ models.py       テーブル定義（User / Department / Project / Kubun / Category / Rank / Sga）
├─ cli.py          システム管理者作成・マスタ投入コマンド
├─ decorators.py   権限チェック・部門スコープ解決
├─ exporters.py    案件のCSV/Excel/PDF出力
├─ auth/           ログイン・パスワード変更
├─ admin/          ユーザー管理・カテゴリー管理
├─ projects/       案件管理表（計上月グルーピング）
├─ analytics/      数字まとめ（予実/損益/カテゴリー別/確度別）と集計ロジック(calc.py)
├─ main/           ホーム
├─ templates/      画面（HTML）
└─ static/         CSS/JS（外部CDNは使わず同梱）
migrations/        DBマイグレーション（Alembic）
tests/             自動テスト
data/              SQLite DB本体（バックアップ対象）
```
